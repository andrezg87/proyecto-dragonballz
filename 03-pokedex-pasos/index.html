Resumen

Mini Pokédex paso a paso

Construimos la misma página siete veces, cada vez con una capa más: HTML, CSS, datos en memoria, datos desde una API, imágenes, TailwindCSS y un remate con buscador, 251 pokémon y carruseles. Cada paso muestra su código comentado, resalta qué cambió y trae el resultado en vivo.

Cómo usar esta guía

Estructura de la carpeta Cada paso vive en su carpeta (paso1 … paso7) y funciona por sí solo: abre su index.html en el navegador. Los pasos 3 a 7 usan TypeScript: el archivo que escribes es main.ts y el navegador ejecuta main.js, que se genera al compilar.
npm install        # una sola vez: instala TypeScript
npm run build      # compila cada main.ts a main.js, revisa los tipos y regenera esta guía
Para clase Pide a los estudiantes que copien la carpeta paso1, la abran en VS Code y avancen paso a paso comparando con esta guía. Los pasos 4 a 7 necesitan internet.

Paso 1 de 7 10 min

HTML: la estructura

Construir el contenido de la página con HTML puro. No hay colores, ni diseño, ni lógica: se ve “feo” a propósito, para entender qué aporta cada capa que agregamos después.

Qué aprendemos
  • Etiquetas semánticas: header, main, section, article
  • Atributos class e id
  • La etiqueta <progress> (una barra nativa)
Qué cambia respecto al paso anterior
  • Creamos index.html con 6 tarjetas escritas a mano, una por pokémon.
ObservaMira lo repetitivo que es copiar y pegar la misma tarjeta 6 veces. Si fueran 1000 pokémon, sería imposible. Ese problema se resuelve en el paso 3.

Paso 2 de 7 15 min

CSS: el diseño

Darle aspecto a la página sin tocar el contenido. El HTML casi no cambia: solo enlazamos una hoja de estilos.

Qué aprendemos
  • Variables CSS (--acento y var(--acento))
  • Selectores de etiqueta, clase, id y descendiente
  • Modelo de caja: padding, borde, margen
  • CSS Grid con auto-fill y minmax
  • :hover y transition
Qué cambia respecto al paso anterior
  • Una línea nueva en el HTML: <link rel="stylesheet" href="styles.css">.
  • Archivo nuevo styles.css con todos los estilos.
ObservaEs exactamente el mismo HTML del paso 1. Cambia solo la apariencia. Eso es separar estructura de presentación.

Paso 3 de 7 20 min

Datos en memoria

Dejar de copiar y pegar HTML. Guardamos los pokémon como datos (un arreglo de objetos) y una función genera las tarjetas.

Qué aprendemos
  • interface para describir la forma de un objeto
  • Arreglos de objetos (se parecen a un JSON)
  • querySelector y innerHTML
  • Template strings con ${...}
  • map() y join() para convertir datos en HTML
Qué cambia respecto al paso anterior
  • En index.html se borran las 6 tarjetas: #lista queda vacío y se agrega un <p id="estado"> y el <script>.
  • Archivo nuevo main.ts (TypeScript) con los datos, tarjeta() y pintar().
  • Dos reglas nuevas en styles.css para el mensaje de estado.
ObservaEl resultado visual es el mismo, pero ahora agregar un pokémon es agregar UNA línea de datos. El navegador ejecuta main.js: TypeScript se compila con npm run build.

Paso 4 de 7 25 min

Datos desde la API (sin imágenes)

Los pokémon ya no están escritos en nuestro código: se piden por internet a PokéAPI con fetch y async/await. Las tarjetas no cambian, solo de dónde salen los datos.

Qué aprendemos
  • async / await y promesas
  • fetch y respuesta.json()
  • Revisar respuesta.ok (fetch no falla con un 404)
  • try / catch y mensajes de carga y error
  • Promise.all: peticiones en paralelo
  • Función genérica getJSON<T>
  • Un adaptador entre la forma de la API y la de nuestro modelo
Qué cambia respecto al paso anterior
  • Se elimina el arreglo en memoria.
  • Nuevas interfaces PokemonApi y ListaApi que describen lo que devuelve la API.
  • Nuevas funciones getJSON, aPokemon, mostrarEstado y cargarPokemones.
  • tarjeta() y pintar() quedan idénticas.
ObservaMientras carga aparece “Cargando…”. Para ver el error, apaga tu internet y recarga: el mensaje en rojo sale gracias al catch.

Paso 5 de 7 10 min

Agregamos las imágenes

Mostrar la ilustración de cada pokémon. La API ya la incluye en su respuesta: solo hay que leerla, guardarla y pintarla con <img>.

Qué aprendemos
  • Leer campos anidados de un JSON (sprites.other["official-artwork"])
  • Tipo unión string | null
  • Operador ?? para valores por defecto
  • <img> con alt y loading="lazy"
  • object-fit para que la imagen no se deforme
Qué cambia respecto al paso anterior
  • Pokemon y PokemonApi suman el campo de la imagen.
  • aPokemon() elige qué imagen usar.
  • tarjeta() agrega la etiqueta <img>.
  • styles.css suma una regla para .card img.
ObservaFíjate en cuántas partes del código se tocan para agregar un dato nuevo: el tipo, el adaptador y la tarjeta. Los tipos de TypeScript te guían a no olvidar ninguna.

Paso 6 de 7 20 min

Remate con TailwindCSS

Reemplazar nuestro styles.css por clases utilitarias de Tailwind. En vez de escribir CSS en otro archivo, describimos el diseño con clases directamente en el HTML.

Qué aprendemos
  • Qué es CSS “utility-first” y sus pros y contras
  • Clases de espaciado, color, tipografía y bordes
  • Diseño responsive con prefijos sm: md: lg:
  • Estados con hover:
  • Record<string, string> para asignar un color a cada tipo
Qué cambia respecto al paso anterior
  • Se agrega el script de Tailwind y se borra el <link>: ya no existe styles.css.
  • index.html se llena de clases de Tailwind.
  • tarjeta() y mostrarEstado() generan clases de Tailwind en lugar de clases propias.
  • Nuevo diccionario COLORES_TIPO: cada tipo tiene su color.
ObservaEl diseño pasa de 1 archivo CSS de ~100 líneas a cero. Lo que ganas en velocidad lo pagas en HTML más largo. Por eso es útil en componentes que se repiten, como estas tarjetas.

Paso 7 de 7 30 min

El remate: buscador, 251 pokémon y carruseles

Juntamos todo y lo subimos de nivel: los 251 pokémon de Kanto y Johto, un buscador, filtro por tipo, un carrusel de imágenes dentro de cada tarjeta, un carrusel automático de legendarios, una ventana de detalle y animaciones al pasar el mouse.

Qué aprendemos
  • Estado de la aplicación + render(): cambiar datos y volver a dibujar
  • Búsqueda y filtros con filter() y el evento input
  • Carga por lotes con Promise.all y barra de progreso
  • Carruseles solo con CSS (scroll-snap) más un poco de JavaScript
  • Delegación de eventos: un solo listener para cientos de botones
  • <dialog> nativo y animaciones personalizadas en Tailwind
  • Type guards: (c): c is [string, string]
Qué cambia respecto al paso anterior
  • Pokemon pasa de una imagen a una galería de hasta 9 (imagenes: Imagen[]), más estadísticas, altura, peso y habilidades.
  • Nuevo estado global (todos, busqueda, tipoActivo, mostrar) y una función render() que lo dibuja.
  • Nuevas funciones carrusel(), detalleHtml(), filtrados() y los eventos de clic y scroll.
  • index.html agrega buscador, filtros, barra de progreso, <dialog> y una configuración de animaciones de Tailwind.
ObservaPasa el mouse sobre una tarjeta: sube, brilla con el color de su tipo y la imagen crece. Escribe char o 25 en el buscador, filtra por tipo, usa las flechas del carrusel de cada tarjeta y haz clic para abrir el detalle.
