¿Qué es una API? 0:00

Una API (Application Programming Interface) es una puerta por la que un programa le pide datos o acciones a otro programa. En web, casi siempre es un servidor que responde peticiones HTTP con datos en formato JSON.

Clientetu página, tu app
GET /pokemon/pikachu →
← 200 OK + JSON
Servidorpokeapi.co

Hasta ahora tus páginas eran estáticas: el contenido estaba escrito en el HTML. Con una API el contenido viene de afuera y tu código lo pinta. Así funcionan las apps de clima, los mapas, las tiendas en línea o las redes sociales.

JSON: el idioma de las APIs

JSON (JavaScript Object Notation) es texto con una sintaxis parecida a los objetos de JS. Viaja por la red como string y en tu código lo conviertes a un objeto de verdad con JSON.parse. fetch lo hace por ti con respuesta.json().

Reglas de JSON Las claves van entre comillas dobles, los textos también, no hay comentarios ni coma final. Valores posibles: texto, número, true/false, null, lista [ ] y objeto { }.

Nuestra API: PokéAPI

pokeapi.co es una API pública y gratuita con datos de pokémon. No pide registro ni llave (API key) y permite peticiones desde el navegador. Usaremos dos rutas:

RutaDevuelve
/api/v2/pokemon?limit=5&offset=0Una lista paginada: count (total), next, previous y results con name y url de cada pokémon.
/api/v2/pokemon/pikachu o /pokemon/25El detalle: id, name, height (en decímetros), weight (en hectogramos), types, abilities, stats, sprites…
Cuidado con las unidades Un pikachu con weight: 60 pesa 6 kg: la API usa hectogramos. Leer la documentación evita estos sustos.

Asincronía: por qué hay que esperar 0:30

Pedir datos a un servidor tarda (cientos de milisegundos). JavaScript no se queda congelado esperando: sigue ejecutando lo demás y avisa cuando llega la respuesta. Predice el orden de los números antes de ejecutar:

Una Promesa (Promise) es un objeto que representa un resultado que llegará en el futuro. Tiene tres estados:

EstadoSignificaCómo reaccionas
pendingTodavía esperando.—
fulfilledSalió bien y trae un valor..then(valor => …) o await
rejectedFalló y trae un error..catch(error => …) o try/catch

async/await es una forma de escribir promesas para que se lean de arriba a abajo. await pausa solo esa función hasta que la promesa termine; solo se puede usar dentro de una función async (en estos ejemplos puedes usarlo directamente arriba del todo).

Ejecútalo varias veces: a veces sale bien y a veces mal. Así se comportan las peticiones reales: pueden fallar, y tu código debe estar listo para eso.

fetch paso a paso

fetch(url) es la función del navegador para hacer peticiones. Devuelve una promesa y necesita dos await: el primero espera la respuesta (estado y encabezados) y el segundo espera y convierte el cuerpo a JSON.

async/await a fondo

Estas tres ideas son el centro de la clase. Los ejemplos usan una función esperar(ms) para ver el efecto de cada await sin depender de internet.

1. Una función async siempre devuelve una promesa

2. Uno tras otro vs a la vez

await en cada línea hace que las tareas se sumen en el tiempo. Si no dependen entre sí, lánzalas juntas con Promise.all.

3. Errores con try / catch / finally

Una promesa rechazada se comporta como una excepción: la capturas con try/catch. finally corre siempre, ideal para apagar el “Cargando…”.

CORS y llaves de API Un navegador solo deja leer una API de otro sitio si ese servidor lo permite (CORS). PokéAPI lo permite; muchas APIs privadas no. Además, nunca pongas una llave secreta en código del navegador: cualquiera la ve en DevTools. Las APIs con llave se llaman desde tu propio backend.

¿Qué es TypeScript? 1:05

TypeScript = JavaScript + tipos. Los tipos describen qué forma tiene cada dato (“esto es un número”, “esto es un pokémon con id y name”) y el editor te avisa de los errores mientras escribes, antes de ejecutar. En una API esto vale oro: te autocompleta los campos de la respuesta y te grita si escribes pokemon.weigth.

app.tstu código con tipos
→
compilador (tsc, Vite)revisa tipos y los borra
→
app.jslo que ejecuta el navegador
Idea clave Los navegadores no entienden TypeScript. Los tipos solo existen mientras programas; al compilar desaparecen. Por eso TS no puede validar lo que llega de la red en tiempo de ejecución (lo veremos con unknown).

En los cuadros de TypeScript de esta página, el editor revisa tus tipos en vivo (panel Problemas) y la pestaña JS generado te muestra lo que queda después de compilar. Aunque haya errores de tipos, el código se ejecuta igual, como en TypeScript real.

Tipos básicos e inferencia

Escribes el tipo después de dos puntos: nombre: string. Si inicializas la variable, TS lo infiere y no hace falta escribirlo. Los tipos primitivos son string, number, boolean; las listas son string[] o Array<string>.

Dos tipos “de escape” que debes conocer: any (apaga el chequeo, evítalo) y unknown (“no sé qué es, compruébalo antes de usarlo”). Más abajo los comparamos.

Funciones tipadas

Tipas los parámetros y el valor que devuelve. Un parámetro opcional lleva ?; una función que no devuelve nada es void.

Uniones, literales y narrowing

Una unión (A | B) acepta varios tipos. Un literal limita a valores exactos ("fire" | "water"). Dentro de un if con typeof TS afina el tipo (narrowing) y te deja usar los métodos correctos. Con strict activo, undefined y null también son tipos que debes manejar.

Interfaces: la forma de un objeto

Una interface describe qué propiedades tiene un objeto y de qué tipo. Es lo que más usarás para describir respuestas de APIs.

Genéricos: tipos con parámetros

Un genérico es un tipo con un “hueco” <T> que se rellena al usarlo. Ya los usas sin saberlo: Array<string> y Promise<number>. También puedes crear los tuyos para escribir una función una sola vez y que sirva para muchos tipos.

Utility types: derivar tipos sin repetir

UtilityResultado
Partial<T>Todas las propiedades opcionales (útil para formularios y PATCH).
Pick<T, "a" | "b">Solo las propiedades que eliges.
Omit<T, "a">Todas menos las que indicas.
Readonly<T>Nada se puede modificar.
Record<K, V>Un diccionario con claves K y valores V.

Tipar la respuesta de la API

Ahora juntamos todo. Describimos con interfaces solo los campos que usamos y creamos una función genérica getJSON<T> que sirve para cualquier endpoint. Observa el autocompletado: escribe pokemon. en el editor de VS Code y verás la lista de campos.

TS no verifica lo que llega de la red getJSON<PokemonApi> es una promesa tuya al compilador: “confía, así viene”. Si la API cambia o responde otra cosa, TS no se entera, porque los tipos desaparecen al compilar. Para datos no confiables, valida en tiempo de ejecución.

unknown y type guards

any deja pasar todo; unknown te obliga a comprobar antes de usar. Una función con retorno valor is Pokemon (type guard) comprueba el dato en ejecución y, si da true, TS lo trata como Pokemon dentro del if.

En un catch Con strict, la variable error de un catch es de tipo unknown. Para leer su mensaje usa if (error instanceof Error) { error.message }.
